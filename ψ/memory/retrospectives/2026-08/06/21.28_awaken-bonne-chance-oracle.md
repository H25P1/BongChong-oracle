## Lessons Learned

- Before the first `git push` to any unfamiliar repo, treat a hook-based rejection as expected rather than exceptional — repos may enforce branch-protection-by-convention (not GitHub branch protection) that's invisible until you try. Where possible, default to a feature-branch-and-PR pattern on the first commit rather than assuming `main` is pushable.
- When copying a "fact" (a count, a date, a status) from one external document into multiple downstream files, check that document's own last-updated timestamp before treating it as current — the cost of a stale figure multiplies with every file it gets copied into, and a public-facing copy (an announcement, an issue) is the most expensive place to have to correct it.
- Reserve structured multiple-choice question tools for questions with genuinely discrete options; route open-ended, single-answer questions (a name, a purpose, a freeform description) through plain conversational text instead — forcing them into a fixed-option UI produces a rejected call and a wasted round trip.
